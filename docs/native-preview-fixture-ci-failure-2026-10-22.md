## R2 hypotheses and R3 diagnostic order

Plausible causes: (1) the mock external fixture does not start/exit 0 with `env_clear` and the restricted PATH; (2) the unlimited-output mock child exits before input write completes, causing writer BrokenPipe and `Unavailable` before overflow decision; (3) short incomplete output incorrectly mapped due to child exit; (4) `/usr/bin/python3` shebang missing on target VM; (5) temp executable permission/mount; (6) changes to child process scheduling/pipe race on the new faster hosted VM; (7) test process/memory limits or deadline. Prioritize fixture execution/termination contract and stdout-vs-stdin race; keep output bounds, cancellation, ownership/reaping and redaction unchanged.

**Minimal diagnostic change first (test-only, no runtime fix yet):**
- Label each malformed external fixture index in assertion, and independently execute each disposable script with test input under the same stripped environment and capture exit/stdout/stderr **without printing raw input or decoder contents**, proving its intended exit/response.
- Do not yet change `preview.rs` semantics. Run this one actual failing integration suite via existing native GTK CI (it remains an automatic dev path-filtered workflow) and inspect case-specific failure before choosing an implementation.
- If the child is valid but the decoder returns Unavailable, instrument the test-only fixture with non-sensitive execution metadata/stream state; inspect writer/reader/exit error precedence. Fix contract without artificial sleeps/retries, ignoring a failure, or broadly relaxing expected outcomes.
