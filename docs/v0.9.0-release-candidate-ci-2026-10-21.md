## Risk and invariants

- CI validation must **not** publish a release, create a tag, touch production `<legacy-dedicated-bucket>`, deploy Worker code, access signing credentials, or promote `dev` to protected `master`.
- The candidate binary must be freshly built from the exact checked-out source with `--locked`, product version `0.9.0`, Debian version `0.9.0-1`, Ubuntu 26.04 amd64 target and package name `rquickshare-native`. Do not relabel `1.0.0-2.debug`; do not present a debug build as a signed public release.
- A package build can be expensive: execute only one candidate gate per substantive release-identity/package change; don't run costly desktop/source checks on documentation commits. Trigger selected source paths only.
- Failure is evidence of a real candidate defect, not permission to weaken cargo, UI tests, artifact verification or APT authenticity checks. Correct underlying cause and rerun the affected final gate.
- `master` workflow tag publisher retains its own protected-branch and source/tag admission; any CI source gate is additive, not a substitute for release-tag Mode B.

## Candidate gate discovery: independent GPG fixture failure

On [Native Linux package smoke 39673531908](https://github.com/morozhenko-apps/rquickshare/actions/runs/39673531908), exact source `16e632e4`, the Worker `native_download` job **passed** and the Rust Core test run reported **783 passed** (other Rust test binaries also passed), but the native Debian job **failed before artifact construction** during Python native signing/APT contract test setup. Six independent Python `setUpClass` fixtures could not perform `gpg --quick-generate-key ... ed25519 sign 0` inside uniquely created TEST ONLY GPG homes: `test_native_apt`, `test_native_ci_archive`, `test_native_ci_signing_key`, `test_native_r2`, `test_native_signer_backup`, `test_native_signer_local`. Their `subprocess.CalledProcessError` reports GPG exit 2; underlying stderr is hidden by `apt.run`, so the exact system message is **not** established. This is not evidence of a wrong real operator signing key or a malformed .deb.

Focused root-cause candidates: long Unix-socket GPG agent paths under the workflow's globally exported `TMPDIR=$GITHUB_WORKSPACE/core_lib/target/disk-test-tmp` (strongest cross-fixture factor; generated test homes and agent sockets are nested beneath it), unwritable/unsafe test directory, unavailable agent service in the CI container, missing GPG component, unsupported crypto algorithm, and runner resource exhaustion. GPG presence is evidenced by successful command invocation; Ed25519 has previously worked in the repository's test-only fixtures. The shared long `TMPDIR` was introduced for Rust tests to avoid unstable temp storage; it is not required for Python/GPG fixtures.

**Bounded test-environment correction (same MODE B scope):** preserve the Rust tests' workspace TMPDIR, but pass `TMPDIR="$RUNNER_TEMP"` only to the existing Python native tests, so each test-created GPG home and its Unix sockets live under the runner's short, task-owned writable temporary directory. Do not weaken assertions, skip cases, modify actual key custody or change production release signing. Let this exact package smoke workflow rerun from the correction and capture its outcome; if still red, inspect a focused GPG agent failure diagnostic without printing secret material. No redundant full 10x release gate is warranted for a test infrastructure path change.

**Separate material public version BLOCKER discovered 2026-10-21:** GitHub actually contains an inherited **`refs/tags/v0.9.0`**, pointing to commit `f850713a75c219299ba797742f4269c6e61a0c84` with message `chore(master): release 0.9.0 (#108)`. The fork also contains `v0.11.5`, from prior upstream release source. There is no current GitHub Release on the fork, but the Git ref is real. Do **not** delete/move/reuse `v0.9.0` or upload new package bytes claiming to be that immutable version. The previously approved choice of Option B (**same production R2 + signed APT**) remains selected, but the **exact new public SemVer** requires user decision under STOP FACTOR before native crate/revision, notes, tag or public signed package name is changed. Verified examples: `v0.9.1` and `v0.12.0` have no current corresponding git refs; `v1.0.0` also absent, but had been reserved for stable future. Recommendation: `v0.12.0` (chronologically after inherited `v0.11.5`) to preserve meaningful SemVer progression. No other deployment architecture change is implied.
