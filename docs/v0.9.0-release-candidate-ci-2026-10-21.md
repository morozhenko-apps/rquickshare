Date: 2026-10-21. Primary **MODE B (Testing)**. This plan is limited to local/CI validation of a candidate; it does not alter application runtime, version, release authority, signed archive, keys, Worker deployment, `master` or Git tag. The owner selected an actual first public `v0.9.0` in [release-readiness-r2-rehearsal-2026-10-20.md](release-readiness-r2-rehearsal-2026-10-20.md), not a test-only R2 channel.

## Risk and invariants

- CI validation must **not** publish a release, create a tag, touch production `rquickshare-native-apt`, deploy Worker code, access signing credentials, or promote `dev` to protected `master`.
- The candidate binary must be freshly built from the exact checked-out source with `--locked`, product version `0.9.0`, Debian version `0.9.0-1`, Ubuntu 26.04 amd64 target and package name `rquickshare-native`. Do not relabel `1.0.0-2.debug`; do not present a debug build as a signed public release.
- A package build can be expensive: execute only one candidate gate per substantive release-identity/package change; don't run costly desktop/source checks on documentation commits. Trigger selected source paths only.
- Failure is evidence of a real candidate defect, not permission to weaken cargo, UI tests, artifact verification or APT authenticity checks. Correct underlying cause and rerun the affected final gate.
- `master` workflow tag publisher retains its own protected-branch and source/tag admission; any CI source gate is additive, not a substitute for release-tag Mode B.
